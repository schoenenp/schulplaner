# schulplaner-simple

The school planner reduced to one fixed product. Planners are still built
exactly like in genbooks — a `Book` with ordered `BookModule`s, generated by the
unchanged `pdf-pipeline` — but schools only fill in:

1. **Planerinfo** — title, subtitle (e.g. school name), school year, Bundesland
   (holidays and school holidays are added automatically)
2. **Termine** — their own dates, printed into the week pages
3. **Umschlag** — keep a preset, upload a JPG/PNG for the front (other three pages blank), or upload a complete 4-page PDF (U1, U2, U3, U4)
4. **Vorschau** — inspect the generated planner; changing content or cover clears the old preview
5. **Bestellen** — separate quantity, address and review screens; billed by invoice

There is no review or confirmation round trip: an order goes straight into
fulfillment. Binding is always saddle stitching (page count padded to a
multiple of 4 by the pipeline).

```
apps/web               Next.js 16 — school area + staff panel (/panel)
packages/pdf-pipeline  copied unchanged from foto-raabe-books
packages/storage       private Hetzner storage (copied) + a dev-only local driver
packages/db            Prisma schema: same planner core, simple orders and settings
scripts/               test runner, demo module generator
```

## How the fixed planner works

- **Panel → Module & Umschläge**: upload PDFs as before. Covers have exactly 4
  pages, the week spread exactly 2 pages (repeated for every week), content
  modules 1–100 pages. Placeholders are the genbooks ones (`BOOK_TITLE`,
  `BOOK_SUBTITLE`, `FROM_TO`, `xA`–`xE`, `xA_Date`–`xE_Date`, `WEEK_FROMTO`,
  `WEEK_NUM`); the upload check reads them from the pipeline's handlers.
  Covers marked "für Schulen" appear in the school's cover choice.
- **Panel → Standardplaner**: the one template `Book` (cover + content in
  print order). School planners copy it and are re-synced to it before every
  preview and order, so content changes reach all planners not yet ordered.
- **Ordering** freezes a copy of the planner (`Book.frozenAt`). Uploaded module
  files are never replaced — a new version is a new module, archived modules
  keep printing for existing orders.
- **Panel → Bestellungen**: Neu → In Produktion → Versendet (optional tracking
  number, school is emailed) → Abgeschlossen, or Storniert. The print PDF is
  generated from the frozen copy and stored with the order. Invoice number and
  "bezahlt" are tracked per order.
- **Panel → Einstellungen** (admins): price tiers (gross per planner), shipping,
  free-shipping quantity, minimum quantity, VAT, default school year, team.

Branding lives in `apps/web/src/brand.ts`, `apps/web/public/brand/` and the
color tokens at the top of `apps/web/src/app/globals.css`.

## Local development

Requires Bun, PostgreSQL and poppler (`pdftoppm`, for previews and cover
thumbnails).

```sh
bun install
cp env.example apps/web/.env.local     # set DATABASE_URL, STORAGE_DRIVER=local
echo 'DATABASE_URL="…"' > packages/db/.env
bun run db:migrate && bun run db:seed
bun run dev                            # http://localhost:3300
bun run demo:modules                   # sample PDFs in demo-modules/
```

Sign in with `PANEL_ADMIN_EMAIL`; in development the sign-in link is written
to the server log (`mail_not_sent_logged_only`) instead of being emailed.

```sh
bun run test         # storage, app and pdf-pipeline tests
bun run typecheck    # all workspaces
bun run build        # prisma generate + next build
```

## Deployment

Coolify + Nixpacks as for the other repos: `nixpacks.toml` pins Node 22.23.4
and installs OpenSSL and poppler. Build with `bun run build`; `bun run start`
applies migrations, seeds module types and settings, and installs the approved
Beige/Gold template if no standard planner is configured. It then starts
Next.js on `PORT`. Give this app its own PostgreSQL database and S3 prefix.
Set `APP_URL` and the mail and storage variables from `env.example`.
Keep `NODE_ENV=production` runtime-only. Check the new app on a separate route
before pointing the existing development hostname at it.

## School experience and custom covers

The school area uses a responsive full-width wizard with a separate screen per
step. Admin forms retain their dashboard layout. Custom covers are immutable
private modules owned by the uploading school. Content synchronization keeps
their cover; frozen order copies reference it for printing. Only the owner and
staff can read its thumbnail.

Uploads accept JPG, PNG or PDF up to 20 MB. Image covers fit the complete image
(with white margins as needed) on U1; U2–U4 stay blank. A PDF must contain four
pages matching the current template cover dimensions. No extra title is overlaid
on custom artwork. All four pages can be checked in the planner preview.
